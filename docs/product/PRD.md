## 1. 프로젝트 개요

### 1.1 배경

기존 코드 이미지 생성 서비스는 코드 편집 과정에서 IDE 수준의 편의성을 충분히 제공하지 못하거나, 불필요한 기능으로 인해 사용 경험이 복잡해지는 문제가 있다.

특히 개발자가 익숙하게 사용하는 줄 삭제, 복제, 이동, 주석 처리 등의 단축키를 제공하지 않는 경우가 많다.

이를 해결하기 위해 IDE의 핵심 편집 기능과 코드 이미지 생성 기능을 결합한 경량 웹 서비스를 개발한다.

### 1.2 제품 목표

**개발자가 코드를 붙여넣고, IDE처럼 편집한 다음, 원하는 스타일의 이미지를 빠르게 생성할 수 있는 서비스.**

핵심 가치:

1. **Performance:** 빠른 초기 로딩과 즉각적인 편집 반응
2. **Editing Experience:** IntelliJ 및 VS Code 단축키 지원
3. **Simplicity:** 최소한의 조작으로 코드 이미지 생성
4. **Customization:** 이미지 스타일과 출력 형식의 유연한 설정
5. **Privacy:** 모든 작업을 사용자의 브라우저에서 처리

### 1.3 대상 사용자

- 기술 블로그 및 개발 문서 작성자
- 코드 예제를 이미지로 공유하는 개발자
- 발표 자료나 포트폴리오를 제작하는 개발자
- 코드 스니펫을 이미지로 빠르게 공유하려는 사용자

## 3. 사용자 시나리오

### UC-01. 코드 이미지 생성

1. 사용자가 사이트에 접속한다.
2. 편집 영역에 코드를 붙여넣는다.
3. 코드 언어가 자동으로 감지된다.
4. 구문 강조 및 코드 창 크기가 자동으로 갱신된다.
5. 사용자가 필요에 따라 코드와 스타일을 수정한다.
6. PNG 이미지 복사 또는 파일 내보내기를 실행한다.

**성공 조건:** 별도의 로그인이나 서버 요청 없이 이미지 생성이 완료된다.

### UC-02. IDE 단축키 활용

1. 사용자가 IntelliJ 또는 VS Code 프리셋을 선택한다.
2. 선택한 키맵이 코드 편집기에 적용된다.
3. 사용자가 단축키를 통해 코드를 수정한다.
4. 편집 내용이 미리보기에 즉시 반영된다.

**성공 조건:** 선택한 IDE 프리셋의 주요 단축키가 정상적으로 동작한다.

### UC-03. 이전 작업 복원

1. 사용자가 코드를 작성하고 스타일을 변경한다.
2. 작성 내용이 브라우저 로컬 히스토리에 저장된다.
3. 사용자가 페이지를 다시 방문한다.
4. 마지막 스타일 설정이 복원된다.
5. 사용자가 히스토리에서 이전 코드를 선택한다.

**성공 조건:** 서버 계정 없이 기존 작업을 복원할 수 있다.

## 4. 상세 기능 요구사항

### 4.1 코드 편집기 (FR-EDIT)

**FR-EDIT-01. 코드 입력**

- 텍스트 입력, 붙여넣기, 선택, 삭제를 지원한다.
- 여러 줄 코드 편집을 지원한다.
- 자동 들여쓰기 및 들여쓰기 조절을 제공한다.
- Undo / Redo를 지원한다.
- 편집기와 미리보기는 동일한 코드 상태를 사용한다.

**FR-EDIT-02. IDE 단축키**

- IntelliJ와 VS Code 키맵 프리셋을 지원한다.
- 사용자가 설정에서 키맵을 변경할 수 있다.
- 키맵 설정은 브라우저에 저장한다.
- Windows 환경을 우선 지원하고 macOS 단축키도 대응한다.

| 기능 | IntelliJ | VS Code |
|---|---|---|
| 실행 취소 | Ctrl+Z | Ctrl+Z |
| 다시 실행 | Ctrl+Shift+Z | Ctrl+Y |
| 줄 복제 | Ctrl+D | Shift+Alt+↓ |
| 줄 삭제 | Ctrl+Y | Ctrl+Shift+K |
| 줄 이동 | Shift+Alt+↑/↓ | Alt+↑/↓ |
| 주석 토글 | Ctrl+/ | Ctrl+/ |
| 들여쓰기 | Tab | Tab |
| 내어쓰기 | Shift+Tab | Shift+Tab |
| 선택 없는 줄 잘라내기 | Ctrl+X | Ctrl+X |

*실제 키맵은 IDE 버전 및 운영체제에 따라 차이가 있을 수 있으므로, 표는 구현 목표로 사용한다.*

- 브라우저 기본 단축키와의 충돌을 최소화한다.
- 편집기에 포커스가 있을 때만 편집용 단축키를 처리한다.
- 단축키 프리셋별 차이를 안내한다.

**FR-EDIT-03. 코드 길이에 따른 크기 조절**

- 코드 줄 수에 따라 창 높이를 자동 조절한다.
- 가장 긴 코드 줄을 기준으로 너비를 계산한다.
- 최소·최대 너비를 설정하여 과도한 가로 확장을 방지한다.
- 줄 바꿈 옵션을 제공한다.
- 미리보기 영역이 화면보다 커지면 스크롤할 수 있다.
- 이미지 출력 시 화면에 보이지 않는 코드까지 모두 포함한다.

### 4.2 언어 및 구문 강조 (FR-LANG)

**FR-LANG-01. 프로그래밍 언어 지원**

초기 지원 언어:

- Java
- Kotlin
- JavaScript / TypeScript
- Python
- SQL
- JSON / YAML
- HTML / CSS
- XML
- Bash / Shell
- Markdown
- Plain Text

**FR-LANG-02. 자동 언어 감지**

- 붙여넣은 코드의 언어를 자동 추정한다.
- 자동 감지 결과를 사용자가 변경할 수 있다.
- 명확한 판별이 불가능한 경우 Plain Text 또는 현재 선택한 언어를 유지한다.
- 사용자가 언어를 수동 선택하면 이후 자동 감지가 해당 선택을 덮어쓰지 않는다.
- 긴 코드에서도 편집 반응성을 저하하지 않도록 감지 작업을 관리한다.

**FR-LANG-03. 테마**

- 여러 Syntax Highlighting 테마를 제공한다.
- Dark / Light 계열 테마를 지원한다.
- 테마 변경 시 편집기와 이미지 미리보기를 갱신한다.

### 4.3 이미지 스타일 (FR-STYLE)

**FR-STYLE-01. 코드 창 디자인**

- macOS 스타일의 빨강·노랑·초록 창 버튼을 지원한다.
- 코드 창의 제목을 수정할 수 있다.
- 언어별 아이콘 표시 여부를 설정할 수 있다.
- 코드 창 모서리 둥글기를 조절할 수 있다.
- 그림자 표시 여부 및 강도를 조절할 수 있다.

**FR-STYLE-02. 코드 스타일**

- 코드 폰트 크기 변경
- 글꼴 선택
- 줄 간격 변경
- 코드 영역 패딩 조절
- 줄 번호 표시 On/Off

**FR-STYLE-03. 배경**

- 단색 배경을 지원한다.
- 그라데이션 배경을 선택적으로 지원한다.
- 코드 창 바깥쪽 배경을 투명하게 설정할 수 있다.
- 투명 배경이어도 코드 창 자체의 배경색은 유지한다.
- 그림자는 투명 영역에서도 정상적으로 출력되어야 한다.

**FR-STYLE-04. 기본 스타일**

첨부한 참조 이미지를 기준으로 다음 프리셋을 기본 제공한다.

- 어두운 코드 창
- macOS 스타일 창 버튼
- 상단 중앙 파일명
- 언어 아이콘
- 둥근 모서리
- 적절한 코드 여백
- 가독성 높은 Syntax Highlighting

### 4.4 이미지 출력 (FR-EXPORT)

**FR-EXPORT-01. 지원 포맷**

| 형식 | 배경 투명 | 파일 저장 |
|---|---|---|
| PNG | 지원 | 지원 |
| SVG | 지원 | 지원 |
| JPG | 미지원 | 지원 |
| WebP | 지원 | 지원 |

- JPG 출력 시 투명 영역은 지정된 불투명 배경색으로 대체한다.
- WebP의 투명도 지원은 정상적인 브라우저 인코딩 환경을 기준으로 한다.

**FR-EXPORT-02. 이미지 해상도**

- 1x / 2x / 3x / 4x 출력 배율을 지원한다.
- 기본 배율은 2x로 설정한다.
- SVG는 벡터 형식을 유지하며 배율 설정의 영향을 받지 않는다.
- 고해상도에서도 글자 및 스타일이 깨지지 않아야 한다.

**FR-EXPORT-03. 클립보드 복사**

- 별도의 이미지 복사 버튼을 제공한다.
- 이미지 복사는 PNG 형식을 기본으로 사용한다.
- 코드 편집기의 일반적인 Ctrl+C는 텍스트 복사로 동작한다.
- 클립보드 API가 허용되지 않거나 실패하면 오류를 안내한다.
- 클립보드 기능은 지원 브라우저의 보안 컨텍스트(HTTPS 또는 localhost)에서 실행한다.

**FR-EXPORT-04. 이미지 품질**

- 이미지와 화면 미리보기의 시각적 차이를 최소화한다.
- 폰트, 줄 간격, 구문 강조, 패딩이 동일하게 출력되어야 한다.
- 모든 코드 줄을 포함한다.
- SVG 출력 결과는 단순 래스터 이미지 삽입이 아닌 벡터 기반 표현을 목표로 한다.
- SVG 내 폰트 및 외부 의존성 호환성을 검증한다.

### 4.5 로컬 데이터 관리 (FR-STORAGE)

**FR-STORAGE-01. 설정 저장**

LocalStorage 등을 이용해 다음 항목을 저장한다.

- 마지막 사용 키맵
- 선택한 언어 및 테마
- 이미지 배경 및 투명도
- 코드 창 스타일
- 폰트 및 패딩
- 출력 형식 및 배율

**FR-STORAGE-02. 코드 히스토리**

- 최근 코드 스니펫을 브라우저 로컬에 저장한다.
- 초기 저장 개수는 최대 20개로 제한한다.
- 중복된 내용은 갱신 방식으로 관리한다.
- 저장 용량을 초과하는 경우 오래된 항목부터 정리한다.
- 항목별 복원 및 삭제를 지원한다.
- 전체 히스토리 삭제 기능을 제공한다.
- 히스토리 저장을 끌 수 있는 옵션을 제공한다.
- 코드 히스토리를 외부 서버로 전송하지 않는다.
- 브라우저 저장소 삭제 또는 시크릿 모드에서는 데이터가 유지되지 않을 수 있음을 안내한다.

## 5. UI / UX 요구사항

### 5.1 전체 화면 구성

데스크톱 기준으로 다음 구조를 채택한다.

**Header**
- 서비스 로고
- 키맵 선택 및 설정 접근
- 코드 히스토리 접근
- 이미지 복사 / 내보내기

**Main**
- 코드 편집 및 이미지 미리보기 영역
- 코드 창은 콘텐츠에 따라 동적으로 크기 조절

**Settings Panel**
- 언어 및 테마
- 배경 및 투명도
- 폰트 및 레이아웃
- 이미지 출력 형식 및 품질

### 5.2 UX 원칙

1. 코드 입력 이후 최소한의 클릭으로 이미지를 생성할 수 있어야 한다.
2. 스타일 변경 결과는 즉시 미리보기에 반영되어야 한다.
3. 이미지 내보내기를 위해 별도 페이지로 이동하지 않는다.
4. 사용 빈도가 높은 이미지 복사 기능을 쉽게 접근할 수 있도록 배치한다.
5. 고급 설정은 기본 편집 흐름을 방해하지 않도록 분리한다.
6. 모바일에서는 가로 공간을 확보하기 위해 설정 패널을 접거나 별도로 표시한다.

## 6. 비기능 요구사항 (NFR)

### 6.1 성능

| ID | 항목 | 목표 |
|---|---|---|
| NFR-01 | 초기 페이지 로딩 | 일반 데스크톱 환경 2초 이내 |
| NFR-02 | 편집 반응 | 300줄 코드에서 체감 지연 최소화 |
| NFR-03 | 스타일 변경 | 즉시 반영 |
| NFR-04 | 이미지 생성 | 200줄 기준 2초 이내 |
| NFR-05 | 번들 크기 | 불필요한 라이브러리 및 언어 리소스 최소화 |

*수치는 초기 성능 목표이며, 네트워크·기기·브라우저를 고정한 환경에서 실제 측정한다.*

### 6.2 아키텍처

- 정적 SPA로 구현한다.
- 백엔드 서버와 데이터베이스를 사용하지 않는다.
- 코드 편집, 스타일 처리, 이미지 생성은 모두 클라이언트에서 실행한다.
- Vercel에서 정적 리소스만으로 배포 가능해야 한다.
- 무거운 언어 및 테마 리소스는 필요할 때 불러온다.
- 초기 페이지 로딩 후 열린 페이지에서는 주요 기능을 오프라인에서도 사용할 수 있도록 한다.

### 6.3 보안 및 개인정보

- 사용자가 입력한 코드는 외부 서버로 전송하지 않는다.
- 코드 히스토리는 브라우저 내부에만 저장한다.
- 불필요한 외부 API 호출을 사용하지 않는다.
- 코드 내용은 실행 가능한 HTML이 아닌 안전한 텍스트로 처리한다.
- 이미지 내보내기 과정에서 임의 스크립트가 실행되지 않아야 한다.
- 사용자 코드 및 히스토리에 대한 명시적인 삭제 기능을 제공한다.

### 6.4 호환성

- Chrome / Edge를 우선 지원한다.
- Firefox / Safari 환경을 검증한다.
- Windows / macOS 키보드 환경을 고려한다.
- 데스크톱 편집 환경을 우선 최적화한다.
- 모바일에서는 기본 편집과 이미지 저장 기능을 제공한다.

- 이미지 렌더링은 DOM 캡처 방식과 전용 SVG 생성 방식을 비교한 뒤 결정한다.
- SVG 출력의 벡터 특성 및 호환성을 고려한다.
- 초기 로딩 성능을 위해 필요한 언어 및 테마 리소스만 동적으로 불러온다.
- 로컬 저장소 접근 오류 및 용량 제한을 처리한다.

## 8. 인수 조건 (Acceptance Criteria)

아래 조건을 모두 충족하면 MVP 구현 완료로 판단한다.

### 코드 편집

- [ ] 코드를 입력하거나 붙여넣을 수 있다.
- [ ] IntelliJ 및 VS Code 키맵을 선택할 수 있다.
- [ ] 선택한 키맵의 주요 단축키가 동작한다.
- [ ] Undo / Redo 및 자동 들여쓰기가 동작한다.
- [ ] 코드 줄 수에 따라 창 높이가 변한다.
- [ ] 긴 코드 줄을 기준으로 너비가 자동 조절된다.
- [ ] 최소·최대 너비 제한이 적용된다.
- [ ] 언어 자동 감지와 수동 선택을 지원한다.
- [ ] Syntax Highlighting이 정상적으로 적용된다.

### 디자인

- [ ] 기본 macOS 스타일 코드 창이 표시된다.
- [ ] 파일명 및 언어 아이콘을 변경할 수 있다.
- [ ] 테마, 폰트, 패딩 등을 변경할 수 있다.
- [ ] 코드 창 외부 배경을 투명하게 설정할 수 있다.
- [ ] 그림자 및 라운딩을 조절할 수 있다.
- [ ] 줄 번호 및 줄 바꿈을 설정할 수 있다.

### 이미지 내보내기

- [ ] PNG 파일을 저장할 수 있다.
- [ ] SVG 파일을 저장할 수 있다.
- [ ] JPG 파일을 저장할 수 있다.
- [ ] WebP 파일을 저장할 수 있다.
- [ ] PNG 이미지를 클립보드에 복사할 수 있다.
- [ ] 1x~4x 출력 배율을 지정할 수 있다.
- [ ] 화면에 보이지 않는 코드도 출력에 포함된다.
- [ ] 투명 배경 및 그림자가 정상적으로 출력된다.
- [ ] SVG 이미지의 벡터 표현과 글꼴 호환성을 확인한다.

### 데이터 및 배포

- [ ] 마지막 스타일 설정이 복원된다.
- [ ] 최근 코드 히스토리를 저장하고 복원할 수 있다.
- [ ] 히스토리 항목 또는 전체 기록을 삭제할 수 있다.
- [ ] 히스토리 자동 저장을 비활성화할 수 있다.
- [ ] 사용자 코드가 외부 서버로 전송되지 않는다.
- [ ] 백엔드 없이 Vercel에서 정상 동작한다.
- [ ] 핵심 성능 목표를 측정하고 검증한다.

## 10. MVP 성공 기준

본 프로젝트의 성공은 기능의 개수가 아니라 **코드 입력부터 이미지 생성까지의 편의성과 속도**로 평가한다.

핵심 검증 지표는 다음과 같다.

1. 사용자가 코드를 붙여넣은 뒤 스타일을 별도로 변경하지 않고도 바로 이미지로 복사할 수 있는가?
2. 개발자가 익숙한 IDE 단축키를 이용하여 불편함 없이 코드를 편집할 수 있는가?
3. 긴 코드에서도 편집 및 이미지 생성 속도가 안정적으로 유지되는가?
4. 별도의 서버 없이 모든 기능을 사용할 수 있는가?
5. 사용자가 다시 방문했을 때 이전 설정과 코드 작업을 이어갈 수 있는가?

**최종 제품 원칙:** Code Snapshot Editor는 웹 IDE가 아닌, IDE 수준의 편집 편의성을 갖춘 가볍고 빠른 코드 이미지 생성 도구를 지향한다.
