# 이슈 20 — 이미지 선명도 비교 계획

[#20](https://github.com/yourjinKR/drop-your-code/issues/20) · PRD FR-EXPORT-01~04

같은 Java 예제와 시스템 모노스페이스 설정으로 SVG→Canvas 출력의 선명도를 비교한다. 코드 위치와 논리 치수를 고정하고, 글꼴·해상도·재샘플링·압축의 영향을 따로 확인한다. 비교 결과를 바탕으로 기본 배율과 렌더링 경로를 결정한다.

## 비교 절차

- [x] `buildSnapshotModel`로 짧은 Java 예제의 모델을 만든다. `encodeSnapshot`으로 SVG, 2×·4× PNG, 2× JPG·WebP를 생성하고 MIME, 픽셀 치수, 바이트 수를 기록한다.
- [x] PNG를 같은 표시 치수에서 비교하고, 2× 파일을 4×까지 확대했을 때와 네이티브 4×를 비교한다. 같은 SVG를 출력 치수에서 직접 그린 결과와 PNG의 디코딩 픽셀을 대조한다.
- [x] 같은 모델의 텍스트를 Canvas에 직접 그려 SVG 출력과 비교한다. 독립 SVG에서 글꼴 대체로 달라질 수 있는 글자 폭을 확인하고, JPG·WebP는 동일한 2× PNG를 기준으로 압축 차이를 측정한다.
- [x] Chrome에서 `Copy Image`를 실행하고 로컬 편집 영역에 붙여넣어 PNG 치수와 픽셀을 확인한다. 동일한 복사 경로를 쓰는 4× 실험과 투명 외부·불투명 코드 창도 확인한다.
- [x] 측정 결과·검증 범위·권고안을 `docs/verification/issue-20-export-fidelity.md`에 기록한다. PNG의 동일 크기와 확대 비교를 함께 확인한다.

## 범위

현재 브라우저 출력과 로컬 클립보드로 비교한다. PNG·SVG·JPG·WebP 및 정적·클라이언트 전용 조건을 유지하고, 외부에 코드나 클립보드 데이터를 전송하지 않는다. 앱 기본값과 렌더링 경로를 바꾸는 결정은 비교 후 다룬다. 고용량 코드 처리 확대는 보류한다.

## 4× 복사 제공

- [x] Properties의 Export 섹션에 `Copy scale`을 추가한다. 기본값은 2×이며 4× 선택 시 도구 모음의 `Copy Image`에 배율을 표시한다.
- [x] 선택한 배율을 기존 PNG 인코더와 클립보드 어댑터로 전달한다. 복사 배율은 다운로드 형식 및 배율과 독립적으로 선택한다.
- [x] Windows Chrome에서 320px 화면의 4× PNG 복사, 바깥 투명·창 내부 불투명, 2× 복귀를 검증한다.

## 레퍼런스 대비 글자 선명도

- [x] 첨부 이미지와 로컬 4× PNG의 픽셀 치수와 같은 키워드의 획을 비교한다.
- [x] 시스템 모노스페이스에서 Cascadia Mono와 Cascadia Code의 우선순위를 높인다. 편집기와 SVG의 글꼴 목록을 한 곳에서 관리한다.
- [x] 실제 4× 클립보드 PNG에서 글자 높이와 획 내부의 픽셀을 다시 비교하고, 관련 브라우저 테스트를 실행한다.

## 도구 모음의 Export 설정

- [x] `Export` 옆 화살표에서 다운로드 형식, 출력 치수, JPG 배경 설정을 연다. 키보드, 바깥 클릭, 좁은 화면에서 조작한다.
- [x] `Copy Image`를 4× PNG로 고정하고 복사 배율 선택을 제거한다.
- [x] 실제 다운로드 4종과 4× 클립보드 PNG를 Chrome에서 검증한다.
