# 이슈 24 — 라이브 편집 캔버스

[#24](https://github.com/yourjinKR/drop-your-code/issues/24) · PRD FR-EDIT-01·03, FR-STYLE-01–03, FR-EXPORT-04

편집 가능한 코드 창을 작업 영역 중앙에 두고 Properties를 기존 위치에서 사용한다. 기존 작업 영역과 도구 모음의 색·타이포그래피를 사용한다. 작업 영역에는 점 격자를 적용하고, 캡처 영역에는 현재 배경과 패딩을 표시해 이미지 범위를 구분한다.

1. `LiveCanvas`에서 CodeMirror가 있는 창에 스냅샷 모델의 너비와 배경 여백을 적용한다. CSS와 모델의 타이포그래피·창 스타일을 맞추고 코드 높이가 내용에 따라 늘어나게 한다.
2. 처음에는 100%로 중앙에 표시하고 좁은 화면에서는 기본 창 너비가 들어오도록 축소한다. 확대·축소는 현재 보이는 중심을 기준으로 한다. `Fit`은 전체를 맞추고 `Reset view`는 초기 배율과 위치로 돌아간다.
3. 빈 영역은 마우스로 끌어 이동하고, `Pan mode`를 켜면 코드 창 위에서도 마우스나 터치로 이동한다. 터치와 키보드는 캔버스의 브라우저 스크롤을 사용한다. `Focus editor`로 화면 밖의 커서 위치에 돌아올 수 있다. 편집 중 텍스트 선택·IME·단축키와 브라우저 확대를 유지한다.
4. 출력은 전체 코드의 기존 정적 SVG 모델에서 생성한다. 최대 출력 너비를 넘는 줄은 내보내기에서 줄을 나누며, 편집 중에는 사용자의 줄 바꿈 선택을 적용한다.
5. 언어·편집·스타일·내보내기 테스트를 단일 작업 공간에서 실행한다. 320px 화면과 데스크톱에서 편집, 창 자동 크기, 이동·Fit·Reset, 이미지 치수와 코드 보존을 확인한다.

## 검증

- `npm run typecheck`와 `npm run test -- --maxWorkers 2` 통과. 단위·통합 테스트 150개를 확인했다.
- Windows Chrome의 프로덕션 빌드에서 Playwright 전체 79개가 통과했다. 화면 밖 편집기 포커스 복구와 네이티브 터치 스크롤을 적용한 뒤 `live-canvas.spec.ts`, `foundation.spec.ts`, `editor-window.spec.ts` 14개를 다시 실행해 통과했다.
- Chrome 모바일 터치 에뮬레이션에서 양축 이동과 스크롤 정지 후 `Reset view` 및 탭으로 편집을 확인했다. 실제 모바일 기기와 OS 입력기는 이 검증 범위에 포함하지 않았다.
