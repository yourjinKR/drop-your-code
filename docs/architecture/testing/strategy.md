# 검증 전략

상태: 작업 1 검증 기반·작업 2 순수 상태 단위 검증 구현, 후속 기능은 검증 설계 · 2026-11-07

기준은 [PRD](../../product/PRD.md)이며 책임 경계는 [아키텍처](../overview.md), 화면 동작은 [UI 명세](../design/ui-spec.md), 기술 선택과 실험은 [ADR 0001](../decisions/0001-foundation.md)을 따른다. Phase 1의 작업별 검증은 [구현 계획](../../plans/phase-1-editor-foundation.md)에 연결한다. 작업 1에서 strict 타입 검사·Vitest/Testing Library/jsdom·Playwright 실행 환경과 셸 smoke 테스트를 추가했다. 작업 2는 Node 환경에서 순수 workspace state·snapshot 입력과 readonly 타입 계약을 검증한다. 실제 결과는 [작업 1 보고서](../../verification/task-1-static-app.md)와 [작업 2 보고서](../../verification/task-2-workspace-state.md)에 기록하며, 아래 편집·렌더링·출력 검증은 해당 기능이 구현된 뒤 수행한다.

## 검증 수준과 역할

| 수준 | 검증 대상 | 한계 및 도구 제안 |
|---|---|---|
| 정적 검사 | TypeScript strict, 모듈 경계, 정적 빌드 결과, 외부 의존성 및 네트워크 호출 경로 | 타입 검사는 실제 키 입력·렌더링 품질을 보장하지 않는다. React·TypeScript strict·Vite·CodeMirror 6을 우선 검토한다. |
| 단위 | 설정 기본값·검증, 키맵 매핑, 상태 전이, 스냅샷 변환, 크기 계산, 저장 정책 | Vitest로 순수 상태를 검증한다. DOM·OS 동작을 흉내 내어 성공했다고 간주하지 않는다. 후속 변환·저장 정책은 해당 구현 시 추가한다. |
| 통합 | 편집기와 공통 상태 동기화, 재설정 시 문서·선택·Undo 유지, 언어 로딩 경합, 저장 실패 복구 | React Testing Library 등을 검토한다. 실제 브라우저에서만 가능한 동작은 아래 수준으로 보낸다. |
| 브라우저 | 실제 입력·붙여넣기·포커스·IME, 스크롤, 비동기 로딩, 다운로드·클립보드·오프라인 | Playwright를 검토한다. 자동화로 증명하지 못하는 OS 예약 키와 권한 흐름은 실제 기기에서 수동 확인한다. |

테스트는 동작 요구를 고정한다. 단순 스타일 값이나 내부 함수 호출 횟수를 그대로 복사한 테스트는 만들지 않는다. 오류 경로에서는 현재 코드·선택·Undo가 손상되지 않는지도 확인한다.

## 키보드와 입력 검증

Windows의 기준은 PRD FR-EDIT-02 표다. 특히 IntelliJ의 Ctrl+Y는 줄 삭제, VS Code의 Ctrl+Y는 Redo이며 서로 섞이지 않아야 한다. Undo, Redo, 줄 복제, 줄 삭제, 줄 이동 양방향, 주석 토글, Tab/Shift+Tab, 선택 없는 줄 잘라내기 각각에 대해 단일 줄/여러 줄 선택/문서 마지막 줄/Undo 후 재실행을 검사한다. 선택 없는 잘라내기는 문서 변경과 클립보드 내용을 모두 확인한다.

- Chrome·Edge/Windows에서 두 프리셋의 실제 키 입력을 먼저 검증한다. macOS 매핑은 Windows의 Ctrl을 일괄 Cmd로 치환하지 않고 IDE 공식 키맵과 대조한 명시적 표를 테스트 입력으로 사용한다. OS/IDE 버전과 키보드 배열을 기록한다.
- 편집기 포커스에서는 해당 명령만 처리하고 설정 입력, 제목 입력, 버튼, 문서 바깥에서는 가로채지 않는다. 프리셋·언어·테마를 바꿔도 커서·선택·Undo가 유지되어야 한다.
- 브라우저 예약 키, OS 입력기/창 전환, 확장 프로그램 충돌을 실제 Windows와 macOS에서 확인한다. 브라우저가 전달하지 않는 조합은 통과로 기록하지 않고 대체 버튼/메뉴·안내 및 지원 한계를 남긴다. 탭/키보드만으로 편집기 포커스를 빠져나오는 경로도 확인한다.
- Ctrl+C/Cmd+C는 텍스트, 이미지 복사는 별도 버튼이다. 한글 IME 조합 중 입력·삭제·Enter/Tab, 영문 전환, 이모지, CRLF 붙여넣기 후 Undo를 브라우저에서 확인한다. 조합 중간 상태를 감지/저장/키맵이 훼손하지 않아야 한다.
- Firefox, 실제 Safari 및 macOS를 Phase 4 호환성 판정에 포함한다. 자동화의 WebKit 실행만으로 실제 Safari·OS 단축키 검증을 대체하지 않는다.

## 기술 가정 검증과 통과 조건

### 렌더러 비교 실험 — Phase 2 시작 전

DOM 캡처와 전용 SVG 생성은 같은 테스트 스니펫·스타일·폰트로 비교한다. 우선 검토 방향과 선택 기준은 ADR 0001을 따른다. 어느 방식도 아직 출력 품질이 검증되지 않았다.

| 확인할 위험 | 실험 | 통과 조건 |
|---|---|---|
| 벡터 표현 | SVG XML을 검사하고 독립 뷰어에서 확대한다. | 전체 화면을 `<image>`로 붙인 결과로 대체하지 않는다. 코드·창 구성은 SVG 텍스트/도형 또는 검증된 벡터 경로로 표현한다. `<foreignObject>`의 뷰어 의존성이 남으면 호환성 미해결로 기록한다. |
| 폰트 | 한글·라틴·이모지·합자·탭, 지연 로드/로드 실패, 대상 폰트 없는 기기, 네트워크 없는 독립 뷰어에서 연다. | 선택 폰트와 대체 폰트 정책이 명확하고 글자 누락·잘림이 없다. 임베딩을 선택하면 라이선스와 독립 파일 동작을 검증한다. 외부 URL 재요청 없이 재현할 수 있어야 한다. |
| 미리보기 일치 | 동일 스냅샷에서 배경·패딩·줄 번호·줄 간격·색·크기를 비교한다. | 줄 수·텍스트·레이아웃 경계·색 값이 일치한다. 안티앨리어싱 차이는 OS/브라우저별 기준 이미지로 분리하고 허용 차이는 실험 결과를 근거로 고정한다. 임의로 큰 오차를 허용하지 않는다. |
| 화면 밖 코드 | 작은 뷰포트에서 300줄·긴 줄을 입력하고 중간으로 스크롤한 뒤 출력한다. | 첫 줄부터 마지막 줄까지, 가로 스크롤 밖 내용까지 포함된다. 편집기 가상화 DOM/현재 화면 크기에 출력 범위가 종속되지 않는다. |
| 래스터 변환 | 동일 SVG/모델에서 네 포맷과 배율 조합을 생성한다. | PNG/WebP의 alpha, JPG 배경 대체, SVG 벡터, 1x~4x 치수, 큰 이미지 실패 안내가 형식별로 확인된다. |

한 방식이 기준을 만족하지 못하면 그 이유와 후속 변경을 ADR에 기록하고 다시 비교한다. 전용 SVG라는 이유만으로 폰트 호환성·미리보기 일치를 확보했다고 판단하지 않는다.

### 지연 로딩과 열린 페이지 오프라인 — Phase 1 기반, Phase 4 최종

1. 캐시가 없는 온라인 상태에서 초기 로드 시간과 요청 리소스를 기록한다. 초기 편집 가능한 시점과 오프라인 준비 완료 시점을 구분한다.
2. 제안한 리소스 준비 절차가 끝난 뒤 네트워크를 차단한다. 아직 선택하지 않은 초기 지원 언어·Dark/Light 테마를 선택하고 편집·키맵 전환·Undo를 실행한다. 이후 단계에서는 미리보기·로컬 저장·네 포맷 내보내기도 실행한다.
3. 초기 편집은 가능하나 백그라운드 준비가 덜 된 시점에 네트워크를 끊어 로딩 실패·재시도·원문 보존과 안내를 확인한다. 단순 동적 import만으로 오프라인을 보장한다는 가정은 허용하지 않는다.

통과 조건은 준비된 열린 페이지에서 주요 기능에 추가 네트워크가 필요하지 않고, 준비 중 실패도 편집을 중단하거나 잘못된 언어 상태를 표시하지 않는 것이다. 초기에 선택한 리소스만 동작하는 결과는 전체 언어 전환 검증 통과로 간주하지 않는다. 새 오프라인 방문/새로고침 보장은 PRD의 열린 페이지 요구와 구분하며 필요하면 별도 결정한다.

### 저장 실패와 용량 — Phase 3

저장 어댑터에 접근 거부, quota 초과, 손상 JSON, 알 수 없는 스키마 버전, 부분 누락 값을 주입한다. 실제 브라우저의 저장소 차단·시크릿 모드·저장소 삭제도 확인한다. 고정 용량을 모든 브라우저의 보장으로 가정하지 않는다.

통과 조건은 편집 가능 상태 유지, 안전한 기본 설정, 미저장 상태 안내, 최대 20개·중복 갱신·오래된 항목 우선 정리, 무한 재시도 없음이다. 정리 후에도 큰 단일 항목을 저장하지 못하면 기존 복원 가능 데이터와 현재 코드를 보존한다. 자동 저장을 끈 후 새 기록이 생기지 않고, 항목/전체 삭제 및 현재 코드 지우기가 외부 전송 없이 동작해야 한다. 삭제 실패를 성공으로 알리지 않는다.

## 이미지·보안 테스트 데이터

출력 검증에는 빈 문서, 한 줄, 200줄, 300줄, 매우 긴 한 줄, 탭/공백 혼합, CRLF, 한글/이모지, 줄 번호 자릿수 변화, 아주 긴 제목, 외부 투명 배경과 강한 그림자를 포함한다. 폰트 준비를 기다린 뒤 캡처하고 브라우저·OS·폰트 버전·배율·뷰포트를 기록한다. 외부 투명 샘플은 가장자리 alpha=0, 그림자 alpha는 중간 값, 창 내부 alpha=255를 확인한다.

`<script>`, HTML 태그, SVG 태그, 따옴표, `&`, URL처럼 보이는 코드는 그대로 텍스트로 표시·내보내져야 한다. 이벤트 핸들러 실행, SVG 스크립트 실행, 외부 리소스 요청이 없어야 한다. 네트워크 요청/URL/본문을 관찰해 입력 코드·히스토리가 분석 도구·로그·외부 API로 전송되지 않는지 확인한다. 같은 출처의 정적 언어/폰트 파일 요청과 사용자 데이터 전송을 구분한다.

## 성능 측정과 실행 계약

PRD 목표는 NFR-01 초기 로딩 2초, NFR-04 200줄 이미지 생성 2초, NFR-02 300줄에서 체감 지연 최소화, NFR-03 스타일 즉시 반영이다. 측정 기기·OS·브라우저 버전·네트워크·캐시·폰트 상태·빌드 모드·반복 횟수를 보고서에 고정한다. 개발 서버의 초기 컴파일 시간을 제품 성능으로 대신하지 않는다.

초기 제안으로 입력→다음 시각 갱신 p95 50ms 이하, 스타일 변경→다음 시각 갱신 p95 100ms 이하를 실험 기준으로 사용한다. 이는 PRD 확정 수치가 아니며 실제 기기 측정 후 이유와 함께 조정한다. 300줄 타이핑/붙여넣기, 언어·테마 전환, 후속 감지·저장 동시 실행을 각각 측정한다. 번들 크기는 PRD에 절대 상한이 없으므로 최초 production 빌드의 초기/지연 청크 크기를 기준선으로 기록하고 증가 이유를 리뷰한다.

다음 명령의 스크립트는 작업 1에서 구현했다. `npm run test`는 한 번 실행 후 종료하며 `tests/unit`·`tests/integration`만 수집한다. 현재 순수 workspace 상태 단위 테스트와 통합 셸 테스트가 있다. 상태 테스트는 Node 환경을 사용하고 readonly의 잘못된 대입은 `npm run typecheck`로 함께 확인한다. Playwright는 기본적으로 build 후 `127.0.0.1:4173`의 production preview를 자동 시작·정리한다. `PLAYWRIGHT_SERVER_MODE=dev`이면 개발 서버를 검사한다. Chromium·Firefox·WebKit 프로젝트를 구분하며 설치한 브라우저에 한해 실행한다. Foundation 테스트는 루트 로드, 이름 있는 셸 영역, 키보드 진입, 화면 폭별 배치, CSS zoom과 페이지 진입 전부터 외부 HTTP/WebSocket·실패 요청·HTTP 오류·전송 본문·콘솔/런타임 오류를 확인한다. 실제 브라우저 확대·IME·OS 단축키의 수동 검증은 별개다.

| 명령 | 기대 결과 |
|---|---|
| `npm run typecheck` | strict 타입 오류 0개 |
| `npm run test -- tests/unit` | 요구 동작/오류 경로의 단위 검증 통과 |
| `npm run test -- tests/integration` | 편집기·상태·설정 연동 검증 통과 |
| `npm run test:browser -- tests/browser` | 해당 단계의 실제 브라우저 시나리오 통과 |
| `npm run build` | 정적 production 산출물 생성; 런타임 백엔드 의존 없음 |

단계별 완료 보고에는 실행 명령·종료 결과·검증 환경·미실행 수동 항목·알려진 제한을 적는다. 최종 MVP 판정은 PRD §8 전체 체크리스트와 이 추적표를 대조한다. 자동 들여쓰기·줄 번호/줄 바꿈은 Phase 1 기반, 폰트/줄 간격은 Phase 2, 1x~4x와 히스토리 관리/삭제·단축키 안내는 Phase 3에서 확보하여 P1 표기 때문에 누락하지 않는다.
